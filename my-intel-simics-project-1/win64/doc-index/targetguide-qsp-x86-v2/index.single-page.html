QSP-x86-v2 Target Guide

1 Introduction

This document describes the details of a specific virtual system. Among other things, it lists the targets available and the various options that can be used when instantiating them in Simics; it also presents the components that can be used to extend them.

Users working with this specific virtual system should read this document in order to understand how the standard models provided with Simics work.

2 QSP-x86-v2 Overview

The QSP-x86-v2 is a made up system that does not exist in real hardware. QSP stands for Quick-Start Platform. The purpose of QSP-x86-v2 is to have an easy system for application development, architectural studies, demos, etc.

The QSP-x86-v2 system comes with device models and a UEFI BIOS. The system allows a generic PC operating system to be installed provided it is compatible with a UEFI BIOS and respects the ACPI tables provided by the BIOS. Note that version 2 of the QSP-x86 has been radically minimized with only modern operating systems in mind. Legacy devices like port I/O based DMA, PS/2 keyboards and mouse, legacy PIC, floppy disks and more have been removed. The QSP-x86-v2 does not support virtual wire IRQ mode. PCI(e) devices are expected to use MSI.

The QSP-x86-v2 package does not contain the processor core which is used by default in the included simulated machines. You need the package QSP-CPU, which contains the default processor core as well as various recent processor cores.

3 Targets

The QSP-x86-v2 comes with multiple target scripts. Invoking ./simics -l in a Simics project on Linux or simics.bat -l on a Windows host will show the targets available.

qsp-x86-v2/hdd-boot

About the Target

The hdd-boot target is a simple target that will attempt a UEFI boot from either disk0 or from disk1, where disk0 has a higher priority. If neither of the disks is created or contains a bootable image, the target will go into UEFI shell.

qsp-x86-v2/user-provided-linux

About the Target

The user-provided-linux target is designed to offer a convenient way to boot a Linux that the end user has built or obtained. The only mandatory element here is the kernel software:linux:kernel. All other parameters are optional, but most likely you will want to use the kernel command line parameter software:linux:cmdline and the root file system software:linux:virtio_rootfs and/or software:linux:initrd parameter. The root file system will use either a VirtIO block device (if the root file system parameter is a disk image) or a VirtIOFS device (if the root file system parameter is a directory).

The requirements on the kernel are that it has drivers for PCI based VirtIO devices, PCI MSI drivers, and that it can be booted by GRUB 2.

Important note: When using VirtioFS, the daemon will always run as the user starting Simics. Hence, the root file system will appear with the user ID of this user. Whether this works depends on the Linux you are running. If your Linux insists that the root file system belongs to the root user, we recommend running Simics under fakeroot.

qsp-x86-v2/yocto-linux

About the Target

The yocto-linux target is a target that boots the Yocto Linux image defined in the parameter software:os_image. Please check the documentation of this parameter to see which Yocto image is recommended. On top of this the image defined in software:os_configuration_diff_image will be applied as a diff. The default image is a prebuilt image from the Yocto project and the default diff image adds the Simics Agent and makes the image more useful to Simics users. The recommendation is to use the default values for the os_image and the diff image.
