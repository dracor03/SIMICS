RISC-V CPU (Package Number 2050) Release Notes

This document contains release notes for the package RISC-V CPU (package number 2050) for Simics 7. The release notes describe new features, bug fixes, and other changes.

Changes Since Version 7.0.0

The following is a list of changes since the initial 7.0.0 release.

7.36.0 (build 7214)

Generic RISC-V CPU model Changes

  • mstatus.SUM and sstatus.SUM are now read-only zero on cores with S-mode but only a bare MMU, as required by the privileged specification since satp.MODE is read-only zero.
  • PMP CSRs for unimplemented PMP entries are now read-only zero, as required by the privileged specification, instead of raising an illegal instruction exception. On cores with fewer than 16 PMP entries this covers pmpaddr0-pmpaddr15 and pmpcfg0-pmpcfg3, and on cores that support privileged specification 1.12 all 64 entries.
  • Reset now clears all implemented PMP registers. Previously only pmpaddr0-pmpaddr15 and their configuration registers were cleared.
  • A bus error when reading or updating a page table entry now raises an access fault matching the original access type (instruction, load or store/AMO) with the virtual address in xtval, instead of a load access fault with the page table entry address.
  • Writing the reserved value 0b10 to the CBIE field of menvcfg, senvcfg or henvcfg now leaves the field unchanged.
  • cbo.clean, cbo.flush and cbo.inval are now permitted when either a load or a store to the cache block is permitted by the page tables and PMP, as required by the Zicbom specification, instead of requiring store permission.
  • Fixed mepc for exceptions raised by cbo.clean, cbo.flush, cbo.inval and cbo.zero executed after other instructions in the same block; it pointed to an earlier instruction.
  • mstatus.SUM no longer allows S-mode to execute from U-mode pages.
  • The TLB is now flushed at reset.
  • A page fault is now raised for PTEs with reserved bits set (bits 63:54, or D, A or U in a non-leaf PTE).
  • Accessing fflags, frm or fcsr while mstatus.FS is Off now raises an illegal instruction exception, and writing them sets mstatus.FS to Dirty.
  • Fixed PMP checks being bypassed when a higher-priority PMP entry only covers part of a page that had already been accessed.
  • Reserved bits in pmpcfg now read as zero, and the reserved permission combination R=0, W=1 is cleared (unless mseccfg.MML is set).
  • Added attribute access_fault_for_misaligned_atomic. When set, misaligned AMO, LR and SC instructions raise an access fault instead of an address-misaligned exception.
  • Misaligned atomic instructions now raise the misaligned exception before any page fault, and write the virtual address to xtval. A failing SC now raises the page faults and access faults the store would have raised.
  • Fixed a crash when an atomic instruction to a memory-mapped device got an access fault. SC and AMOs now raise a store/AMO access fault in this case instead of a load access fault.
  • minstret no longer counts exceptions and interrupts, nor the instruction that writes minstret.
  • WFI in U-mode on cores without S-mode no longer traps when mstatus.TW is clear.
  • SRET in U-mode now raises an illegal instruction exception instead of a virtual instruction exception or no exception.
  • SRET in M-mode no longer traps when mstatus.TSR is set.
  • Writes to sip can no longer set STIP or SEIP; only SSIP is writable.
  • EBREAK and C.EBREAK now write the address of the instruction to mtval/stval.
  • mcounteren, scounteren and hcounteren are now 32 bits wide on RV64 cores.
  • On cores that implement fewer than 32 hardware performance counters, mhpmcounter3-mhpmcounter31, mhpmevent3-mhpmevent31 and hpmcounter3-hpmcounter31 now all exist, as required by the privileged specification. The ones for unimplemented counters are read-only zero instead of raising an illegal instruction exception.
  • mhpmcounter3-mhpmcounter31 are now writable counters that do not count, instead of being hardwired to zero.
  • Reserved values are no longer accepted in mstatus.MPP (2 is always reserved), medeleg (bit 16, and the guest bits without the H extension) and mideleg (machine-level interrupts).
  • Bit 0 of mepc, sepc, vsepc and mnepc is now hardwired to zero, and so is bit 1 on cores without the C extension. On cores with C, bit 1 reads as zero while C is disabled in misa.
  • FENCE with both the predecessor and successor sets empty is now executed as a HINT (no operation) instead of raising an illegal instruction exception.
  • FENCE and FENCE.I instructions with non-zero reserved fields (fm, rs1 and rd, and the immediate of FENCE.I) now execute normally instead of raising an illegal instruction exception.
  • Custom CPU classes: added the Zcb, Zcmp and Zcmt parameters. The combination of parameters is now validated, for example Zcb, Zcmp and Zcmt require the C extension and Zcmp and Zcmt cannot be combined with C and D, S requires U, H requires S and mmu_mode_support requires S. An invalid combination no longer creates a class.
  • Added the code size reduction extensions Zcb, Zcmp and Zcmt, controlled through the extensions port. They are only available when misa.C is set, Zca, Zcf and Zcd are controlled by misa.C. Zcmp and Zcmt cannot be combined with the C and D extensions.

7.35.0 (build 7201)

Generic RISC-V CPU model Changes

  • Added more details to the output of the status and pregs (print-processor-registers) commands. The package now requires Simics-Base 7.108.0.
  • Cores with Smrnmi: Fixed WFI not waking up on interrupts while mnstatus.NMIE is clear.

7.34.0 (build 7173)

CPU generic

  • Fixed a memory leak in the event queue handling.

RISC-V Generic Package Changes

  • Added new model riscv-rv64h, which is similar to rv64 but with Hypervisor extension enabled.

7.33.0 (build 7172)

Generic RISC-V CPU model Changes

  • The reset_vector and nmi_vector ports, which allow the vectors to be set through an interface, are now deprecated. The recommended approach is to implement a register bank and set the reset_vector and/or nmi_vector attributes to point to the desired register within that bank.
  • The reset_vector and nmi_vector attributes can now be configured to reference a remote register with an optional offset. The address will be read from that register whenever it is required, allowing the same register to be shared across multiple harts. Two additional read-only attributes, read_reset_vector and read_nmi_vector, have been added to retrieve the effective address regardless of whether it is configured locally or remotely.
  • mcycle and minstret are now reset to zero when cores are reset.

7.32.0 (build 7164)

CPU generic

  • The package now requires Simics-Base version 7.89.0 or later.

7.31.0 (build 7161)

Generic RISC-V CPU model Changes

  • Exceptions while in RNMI-mode (mnstatus.NMIE cleared) will now go to the nmi_vector. The attribute rnmi_exception_vector is still present to make checkpoints work but there is no functionality behind it.

7.30.0 (build 7156)

CPU generic

  • Instrumentation that only increments counters (such as instruction-histogram) now runs slightly faster and consumes significantly less memory, improving performance in workloads with large code footprints such as operating system boots.

7.29.0 (build 7150)

Common

  • The signing certificate on Simics packages has been updated.

7.28.0 (build 7145)

CPU generic

  • Added ports physical_memory_inspection and logical_memory_inspection to inspect the physical memory attached to the processor. These ports add the architectural atoms representing the current state of the processor before forwarding the transaction to the physical_memory (fixes SIMICS-22568).

7.27.0 (build 7138)

Generic RISC-V CPU model Changes

  • A full reset is now done in the last phase of creation of a core. Execution will start at the reset_vector set during creation.

7.26.0 (build 7128)

Generic RISC-V CPU model Changes

  • Added attribute rnmi_exception_vector for coder with Smrnmi enabled that can be used to set the vector used for exceptions while cpu is in machine mode and mnstatus.NMIE is cleared.

7.25.0 (build 7122)

Generic RISC-V CPU model Changes

  • Fixed a bug where reading certain register values with the TCF debugger would cause an assertion to trigger.
  • The attribute reset_misa will now complain if a value with not supported extensions is set.
  • The CLI-command list-riscv-custom-cpu-parameters is now lifted from tech-preview. It will list options available for customization of most RISC-V cores. There is an example in src/extensions/riscv-custom-cpu/.
  • Improved customization options, more extensions added to several CPU-classes.

7.24.0 (build 7117)

CPU generic

  • Fixed an invalid dependency from CPU models using the new simgen to the old simgen, causing problems building the CPU model on systems without 32-bit support.

7.23.0 (build 7116)

Generic RISC-V CPU model Changes

  • Added support for Smrnmi, Extension for Resumable Non-Maskable Interrupts. Note, it is not available on all targets.

7.22.0 (build 7115)

CPU generic

  • Instruction breakpoints for physical addresses reported the address of the beginning of the instruction even though the breakpoint starts on the second half of a page crossing instructions. This is different from breakpoints triggered by transactions sent to the memory system, which do not know about the beginning of the instruction. This bug is now fixed, and only the part which actually crosses the breakpoint is reported, bug SIMICS-9695.

7.21.0 (build 7111)

Generic RISC-V CPU model Changes

  • The ATOM riscv_io_error_ret is now added to all transactions.

7.20.0 (build 7108)

RISC-V Generic Package Changes

  • The riscv-interrupt-controller model has been moved to package RISC-V-Simple, package number 2053.

7.19.0 (build 7088)

Generic RISC-V CPU model Changes

  • Fixed off-by-one error in PMP range checking.

7.18.0 (build 7084)

CPU generic

  • Fixed a rare bug where the results of Just-In-Time (JIT) compiled code could be inconsistent with those produced by the interpreter. This inconsistency occurred when the memory hierarchy replaced the value to be written, which was incorrectly ignored by the JIT compiler. This issue has now been corrected (fixes HSD-14024141137).

7.17.0 (build 7079)

CPU generic

  • New probes were added to measure the wall clock time spent in uncore simulation. Currently this is only for memory mapped IO activities. The new probe-kinds are: cpu.time.uncore, cell.time.uncore, and sim.time.uncore.

7.16.0 (build 7075)

7.15.0 (build 7072)

CPU generic

  • Fixed a bug in the instrumentation framework. Previously, removed instrumentation callbacks could continue to block VMP from executing, bug SIMICS-23063.

7.14.0 (build 7069)

Generic RISC-V CPU model Changes

  • Added port nmi_vector exposing interface uint64_state. It can be used to update nmi_vector during runtime.
  • Corrected unaligned memory accesses crossing page boundary.

7.13.0 (build 7064)

CPU generic

  • transaction_translators that needs to perform side effects on a page access can now deny a inquiry direct memory lookup from CPUs. The CPU will follow up with a real access and then retry the direct memory lookup. Before this change, such behavior by transaction_translator would significantly degrade the runtime Simics performance (fixes SIMICS-19940).

7.12.0 (build 7063)

Generic RISC-V CPU model Changes

  • Updated all RISC-V CPU:s to build with Simgen 2.0.1

7.11.0 (build 7058)

Generic RISC-V CPU model Changes

  • In some cases, the RISC-V models now start JIT compilation earlier, since some corner-cases previously did not initiate JIT compilation. This could result in slightly higher performance.

7.10.0 (build 7055)

Generic RISC-V CPU model Changes

  • Implementation of atomic instructions LR and SC that accesses device registers or not yet accessed memory now acquires the cell instead of requesting serialized execution.

7.5.0 (build 7019)

Generic RISC-V CPU model Changes

7.4.0 (build 7017)

Generic RISC-V CPU model Changes

  • The print-pmp-regions command is added. It will list PMP-regions currently setup in the PMP-registers.

7.3.0 (build 7016)

CPU generic

  • The size of the module global JIT area has increased from 64MB to 256MB. Workloads with very large instruction footprint, could fill up the entire JIT code area, resulting in a flush and slow recompilation.
  • Linux only: If the kernel supports Transparent Huge Pages (THP), the JIT code area now makes use of 2MB TLB mappings. This could slightly increase execution performance.

Generic RISC-V CPU model Changes

  • New interface riscv_custom_csr added enable implementation of custom CSRs.
  • New interface riscv_instrumentation_action added to simplify implementation of custom instruction semantics.

7.2.0 (build 7009)

Generic RISC-V CPU model Changes

  • Don’t allow instructions to update locked pmpaddr-registers.
  • Improved checkpoint recoverability for mcycle and minstret (fixes SIMINT-1612).

7.1.0 (build 7007)

  • Updated the batch (.bat) files in the bin folder so that they do not leak environment variables to the current cmd.exe command shell on Windows (fixes SIMICS-21906).
