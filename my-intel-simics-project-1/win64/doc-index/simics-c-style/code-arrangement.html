7 Code arrangement

The functions and variables exported from a .c file should be declared in the corresponding .h file. That header should be included first in the .c file.

This practice forces header files to be independent so that they do not require any other headers to be included first, which simplifies their use elsewhere. Making a unit include its own header will check that the definitions in both files agree.

Function prototypes in the header should not be declared extern; that keyword is superfluous there. The header should only contain the types actually needed for other units to interface with it. Where possible, opaque struct and class types should be used.

Any functions or variables that are not used outside the unit should be declared static.

Reorder functions to avoid the need of forward declarations where possible.

Forward declarations are just a pointless exercise required by the language, needing extra maintenance and taking up space. Ordering functions in the calling order also makes it easier to navigate in the code since it imposes a consistent direction to look for functions and their callers.
