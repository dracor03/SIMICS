10 Other considerations

Use string methods wisely. There is often a function that does what you need, so look in the manual before writing a loop.

In particular, do not use indexing and slicing when testing for prefixes/suffixes. Use startswith()/endswith() instead:

if s[:3] == 'bar':       # BAD
if s.startswith('bar'):  # GOOD

Regular expressions are powerful but tricky to get right and can be slow; only use them when no better alternative exists. In particular, the string .split() method is a fast and easy way to break up a string into parts.

Always use raw string literals when specifying regular expressions:

m = re.match("[a-z]+\b", s)        # BAD (and incorrect!)
m = re.match(r"[a-z]+\b", s)       # GOOD (and correct)

If you must compare object types, use isinstance() rather than using type() since it allows for subtyping:

if type(x) == type(1):   # BAD
if isinstance(x, int):   # OK

Remember that the empty list, tuple and dict are false in boolean contexts. Use this for clearer code:

if len(mylist) > 0:      # CLUMSY
if mylist:               # BETTER

Of course, you must be sure that you test the right thing; a polymorphic variable could hold a string or None, for instance.

Keep in mind that tuples with a single element require a trailing comma:

print("Value=%r" % (value))      # WRONG
print("Value=%r" % (value,))     # RIGHT

(Consider what happens in the code above if value is a tuple.)

Use the // operator, not /, for integer (truncating) division. This makes the code more robust and also makes a migration to Python 3.x easier.
