7 Exceptions and finishing

Be precise in what exceptions are caught to avoid hiding bugs. It is very rarely a good idea to catch all exceptions:

try:
    x = something()
except:                  # BAD
    x = theother

Put as little code as possible inside try clauses, to avoid catching exceptions you did not anticipate.

Do not use the old string-based exceptions; always raise class-based exceptions.

Avoid using exceptions to handle missing elements in dictionaries; there are usually a method that gives a cleaner solution:

try:                               # BAD
    x = pet[name]
except KeyError:
    x = little_piggy

x = pet.get(name, little_piggy)    # GOOD

In general, exceptions are preferred for errors and non-local conditions and control transfer rather than for local control flow, since they are harder to follow than plain conditionals.

To run clean-up code (such as closing files, deleting temporary things, etc), either use the try..finally construct or the with construct, instead of trying to cover all possible exit paths from a chunk of code.
