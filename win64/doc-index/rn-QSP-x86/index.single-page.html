Quick-Start Platform x86 (Package Number 2096) Release Notes

This document contains release notes for the package Quick-Start Platform x86 (package number 2096) for Simics 7. The release notes describe new features, bug fixes, and other changes.

Changes Since Version 7.0.0

The following is a list of changes since the initial 7.0.0 release.

7.66.0 (build 7214)

QSP-x86-v2

  • Update BIOS to QSPv2_r_1_9_0.fd. The change reallocates flash space from FVMAIN_COMPACT to the SEC FV so microcode patches can be embedded as FIT type 1 entries; the overall flash layout is unchanged. The new version is fully backwards-compatible and it replaces all uses of QSPv2_r_1_8_0.fd.

7.65.0 (build 7210)

Blueprints of the Quick Start Platform for x86 v2

  • RMUG4 (remap_unit_gen4) initialization is now performed by the QSPv2 blueprint itself instead of the rmug4_helper.py target script, removing duplication across target scripts and making it available when the blueprint is used directly. New parameters hardware:remap_unit:rmug4:paw, hardware:remap_unit:rmug4:x2apic_opt_out and hardware:remap_unit:rmug4:with_atsr configure the DMAR table generated for the RMUG4 remap unit. A new parameter hardware:simulation:create_cell (default FALSE) controls whether the blueprint creates its own simulation cell.
  • The top-level object created by the QSPv2 blueprint now has an attribute memory_megs returning the DRAM size in megabytes. This is used by the print-target-info and list-target-info commands.
  • QSPv2 now uses CPU blueprints instead of CPU components. The blueprints are selected with the parameter processor:class that was previously used to select the component class. In order for a CPU blueprint to be usable the following applies:
    • The module containing the CPU blueprint must be associated with the Simics project.
    • The Simics module must also be a proper Python package with an __init__.py file.
    • With the value of processor:class being (for example) x86-foo the function name for the blueprint has to be bp_processor_x86_foo.
    • The same file that defines the blueprint function must define a state class socket, with members mem_space, port_space, apic_bus, broadcast_bus, and cell, all being ConfObject types to store references to the respective objects within the QSPv2.
    • A blueprint instance for a given CPU shall take its configuration from the config class CPUParams as defined in the x86-bp module.
    • The CPU blueprint can be decorated with the @bp_legacy_comp decorator.

Generic PC support module

  • Added attribute fwd_msg_to_iommu to the PCI upstream dispatcher. When set, non-interrupt upstream PCIe messages (e.g. ATS invalidation completions) are forwarded to the IOMMU remap unit instead of being dropped.

QSP PCI Components

  • Removed the dummy clock workaround from qsp_usb_blueprint and the associated qsp_usb_clock_available function, since a working queue is now guaranteed to be available at object creation time. The USB controllers now enable frame list and async/periodic list polling directly instead of requiring a separate call once a clock became available.

QSP-x86-v2

  • RMUG4 initialization is no longer performed by a helper script invoked from the target .yml.include files; it has moved into the QSPv2 blueprint itself. See the qsp-x86-v2-bp release notes for details.

7.64.0 (build 7196)

Blueprints of the Quick Start Platform for x86 v2

  • The top-level object created by the QSPv2 blueprint now offers custom info and status commands. The info command shows the configuration data used when the blueprint was expanded. The status command shows the state of the connectors.

7.63.0 (build 7193)

QSP-x86-v2

  • Update BIOS to QSPv2_r_1_8_0.fd. The BIOS now supports booting from PCIe-connected AHCI CDROMs and includes MNP, SNP, IPv4, IPv6, and VLAN network drivers. The new version is fully backwards-compatible and it replaces all uses of QSPv2_r_1_7_0.fd.

7.62.0 (build 7192)

Blueprints of the Quick Start Platform for x86 v2

  • Fixed a bug where one could not create more than 14 root ports, because the device number of the VGA device was fixed at 15 and the 15th port would collide in the device numbers. The device number of the VGA device is by default 15 but will be pushed upwards if more than 14 root ports are created. This allows to create the envisioned maximum number of root ports, which is 20.

Generic PC support module

  • Increased the maximum port ID for the generic root port class from 10 to 20 to enable creating more ports in a single platform.

7.61.0 (build 7188)

QSP-x86-v2

  • Add a command list-bios-build-shas to the QSP v2 top-level object to allow inspecting the commit SHAs of the source repositories used to build the loaded BIOS.
  • Update BIOS to QSPv2_r_1_7_0.fd. The new BIOS has improved source traceability. When the QSP v2 is booted into EFI shell, the command BuildInfo will show the commit SHAs of all repos used to build it. The new version is fully backwards-compatible and it replaces all uses of QSPv2_r_1_6_0.fd.

7.59.0 (build 7185)

QSP-x86-v2

  • Update BIOS to QSPv2_r_1_6_0.fd. This makes the BootOrder EFI variable persistent between simulated reboots, which enables efibootmgr settings made from within Linux running on the QSPv2 to take effect. This also means that a boot device selection made via the attribute selected_boot_option of the Simics UEFI device (<qspv2>.css.mpss.simics_uefi) only takes effect on the initial boot. During simulated reboots the selected boot option will be ignored as the now persistent BootOrder is then reused. The new version is fully backwards-compatible and it replaces all uses of QSPv2_r_1_5_0.fd.

QSP-x86-v2

The selection persists over reboots and overwrites the selection made in attribute video_mode of the Simics UEFI device. The new version is fully backwards-compatible and it replaces all uses of QSPv2_r_1_3_0.fd.

  • Update BIOS to QSPv2_r_1_3_0.fd. This increases the MEM64 PCI resource window to 16TiB to accommodate resource-hungry PCIe endpoints, and includes internal cleanup and restructuring. The new version is fully backwards-compatible and it replaces all uses of QSPv2_r_1_2_0.fd.

7.21.0 (build 7063)

QSP-x86

  • The user-provided-linux target now uses the boot device selection feature offered by the Simics UEFI device (SIMICS-17186).
  • The hardware definition for new-style targets (hardware.yml) now has an additional parameter hardware:processor:do_not_initialize_mtrr that (when set to true) prevents the motherboard component from initializing the MTRR registers of the cores. The initialization was done for legacy workloads that did not use the UEFI BIOS. For workloads that use the UEFI BIOS this is no longer needed. With all new-style targets using the UEFI BIOS, the default for the parameter is hence true (HSD-22013229935).
  • Version 2 of the QSP BIOS is now in full 64 bit mode (SEC, PEI and DXE), understands SR-IOV devices during PCI enumeration and has a significantly increased 64 bit PCI resource window in order to handle SR-IOV devices with a large number of virtual functions. The new BIOS file is named SIMICSX58X64_2_0_0_r.fd and is fully backwards compatible and it replaces all uses of SIMICSX58IA32X64_1_5_0_r.fd. Hence, BIOS SIMICSX58IA32X64_1_5_0_r.fd has been removed from the package.

X58 ICH10 Hierarchical Components

  • Added new configuration attribute do_not_initialize_mtrr to prevent MTRR register initialization by the component. This is needed for legacy workloads and hence defaults to false to prevent existing setups from breaking. When using a UEFI BIOS, the attribute should be set to true (HSD-22013229935).
