Intel® Simics® Simulator Release Notes

Changes Since Version 7.0.0

The following is a list of changes since the initial Simics 7.0.0 release. The described changes are the changes done to the package Simics Base (package number 1000). Changes to other packages are described in the release notes accompanying a particular package.

7.113.0 (build 7214)

Core

  • Added DTI-ATS-related types in simics/arch/arm.h.
  • The Python bindings for functions SIM_event_post_time, SIM_event_post_cycle and SIM_event_post_step no longer leak a reference to the user_data argument.

Debugger

  • Stack frames, stack depth, and frame based symbol lookups requested while the simulation is running, for example from an event callback, no longer return a stale stack trace cached from an earlier point in time.
  • Improved error handling for disallowed register accesses, such as reading a non-readable register (fixes HSD-21045855961).
  • Updated PCI handling to not require a component based target hierarchy.

Device API

  • Added DTI-ATS related types in simics/arch/arm.h.

PCIe DML library

  • Root Ports now set the Received System Error bit in the Secondary Status register when receiving an ERR_FATAL or ERR_NONFATAL message on the secondary interface.

Project Setup Script

  • In a project with a Python virtual environment, the project’s project-setup and addon-manager scripts now run with the Python that the environment was created from. This allows them to update or remove the environment also on Windows.
  • When --no-venv is used in a project that already has a Python virtual environment, project-setup will keep using it and no longer removes the python wrapper script, unless --force is used. A missing wrapper is recreated. This affected addon-manager, which caused Simics to run without PYTHONUTF8=1 (fixes HSD-15020014896).

UEFI Firmware Tracker

  • Added Platform Runtime Mechanism (PRM) support. Any PRM modules found by the tracker will be preserved even after hand-off, similarly to how SMM modules are preserved. PRM tracking is only available on x86, where it is enabled by default. To disable PRM support, use -disable-prm-tracking flag used with <uefi_fw_tracker>.detect-parameters. If any of DXE or Hand-off tracking are disabled, the PRM tracking will be disabled. PRM modules are identified by their PRM Module Export Descriptor, without checking that the firmware publishes the PRM ACPI table, so PRM tracking should be disabled for firmware built with ACPI or PRM disabled (fixes HSD-15017882167).

VMP

  • Version 1.16.28 plugged another host PKRU state leak only affecting Linux < 5.2.

7.112.0 (build 7211)

Breakpoint Manager

  • The bank_instrumentation_subscribe interface was restricted to disallow calls to remove_connection_callbacks, and bp.bank.break -once was updated to respect this restriction. This helps resolving some use-after-free violations detected by address sanitizers.

Core

  • Incorrect deprecation warnings for command-line options were fixed (fixes SIMICS-23756).
  • Warn if simics_start.py was loaded for a different module than the one that was ultimately loaded. Fixes part of SIMICS-23143.
  • Make the recently added command list-low-level-breakpoints unsupported under internals.

VMP

  • Version 1.16.27 stopped leaking host PKRU state into the simulation while the same state is managed by XSAVE.
  • Version 1.16.27 is now compatible with Linux 7.2. SIMICS-23753

7.111.0 (build 7208)

Core

  • Fixed a rare deadlock where a simulation with multiple cells could hang indefinitely.

Instrumentation

  • The transaction-tracer tool is now officially released. Do help new-transaction-tracer for more information.

PCIe DML library

  • Fix PCIe ports such that they now use the SERR# Enable bit in the Bridge Control register rather than the Command register when deciding to forward messages received on the secondary interface to the primary interface.
  • Legacy INTx interrupt signaling is now deasserted in the AER implementation when a Root Error Status register is cleared.
  • The pcie_register_write_action template now invokes the pcie_write_action() method before the field writing dispatching has taken place. A new template, pcie_register_write_action_post has been introduced which has the previous behavior of the pcie_register_write_action template. The method name in that template has a new name.
  • Added FPB Routing support for PCIe Memory transactions.

Target parameters

  • Parameters listed in provides can now be set to NIL by the providing script, even if not declared with allow_empty.

VMP

  • Version 1.16.26 corrected step accounting on Efficient-cores. SIMICSTS-1760
  • Version 1.16.26 addressed several cases of truncation and underflow of user-provided inputs. SIMICS-23681

7.110.0 (build 7206)

Code coverage

  • Fixed an issue where functions would not be added if a an error with opening a symbol file had occurred prior to adding a path map. This problem would expose itself as no functions in the report.

Core

  • Trying to load a checkpoint with string attributes that are not valid utf-8 now causes a parse error instead of printing an internal error and proceeding with the parse and load of the checkpoint. This fixes part of SIMICS-11105.
  • Added the command list-low-level-breakpoints which lists some of the available breakpoints not directly handled by the <bp-manager>. Notice that of some <bp-manager> breakpoint types are implemented using the breakpoints listed by list-low-level-breakpoints, so the set of breakpoints <bp-manager>.list and list-low-level-breakpoints could overlap.
  • Simics now reports proper errors when you try to run scripts that are not valid utf-8 files. This fixes part of SIMICS-11105.
  • The memory-map command now clearly displays if an address range has multiple conflicting mappings, referred to as ambiguous mappings in Simics. Previously the memory-map command just displayed those ranges as empty.

Probe Monitors

  • Changes in the reports generated by the html-report and html-diff-report commands:
    • Graphs are now arranged in optional groups, such as Performance Overview, Workload Analysis, VMP, Scheduling, Host, Platform Model Activity, Module Profile, Instructions and JIT. Only the most important groups are shown by default, which roughly halves the number of graphs a user initially sees.
    • A new “Graphs” menu at the top of the Graphs section shows how many graphs are visible and lets the user choose which groups to show. Groups with more detailed graphs (VMP, Host and JIT) have a Details sub-group. Checking a group turns on all its sub-groups, while each sub-group can also be shown on its own. “Show all” and “Defaults” buttons are available, and the choice is remembered between reports.
    • Each group has its own colour, shown as a border and a tag on the graph headers, so it is easy to see which group a graph belongs to.
    • The CPU class and cell pages use the same groups as the main page.
    • The separate vmp.html page has been removed. Its graphs are now in the VMP and VMP Details groups on the main page.
    • New host graphs: Simics execution thread CPU time and scheduler events, host CPU work time, host CPU frequency over time, host CPU frequency limits, and host temperature at the end of the run.
    • “Show internals” no longer hides or shows graphs. It now affects only probe tables and analysis findings, and is shown only on the main page.

Probes Framework

  • Added the Probe_Key_Histogram_Options property for configuring histogram presentation, including displaying values without percentages or aggregation of omitted values.

Probes Singleton

  • The probes framework has been refactored. Many probe classes are now registered only after the enable-probes command has been run, directly or implicitly by another command.

Processor API

  • The virtual_data_breakpoint and virtual_instruction_breakpoint interfaces have a new optional method, list, which lists the breakpoints added through the interface. It is only present in modules with build-id 7204 or later.

7.90.0 (build 7166)

Core

  • Commands pcie-memory-read, pcie-memory-write, pcie-io-read, pcie-io-write, pcie-config-read, and pcie-config-write now have a new argument pcie-downstream-port which can point to any object of class pcie-downstream-port or pcie-downstream-port-legacy. The access will then be issued to this downstream port. This argument is mutually exclusive with hierarchy. Refer to the respective command’s help for details.
  • In the confclass library, it is no longer allowed to use a container type instance (for example []) as attribute default value. The reason this is not allowed is that the default value would otherwise be shared between all instances of this class. For example, if an attribute abc is declared with cls.attr.abc("[i*]", default=[]), update by changing the default value from [], to either list, or lambda: []. That is, a callable that takes no argument and returns a new instance of the default value. The callable will be called each time the class is instantiated (fixes SIMICS-23520).

Debugger

  • Updated suspend reason to differentiate between breakpoint and watchpoint (fixes SIMICS-23573, DBG-23226).

PCIe DML library

  • Added CLKREQ output signal to PCIe Devices. This implements the specification prescribed behavior of the Enable Clock Power Management bit in the Link Control register, which applies to Upstream Ports. CLKREQ in Upstream Ports is currently controlled by the PM Capability Device Power Management States, asserting the signal in D0 and deasserting it in D1/D2/D3. The signal is also added to Downstream Ports, but there is currently no mechanism implemented for controlling it in those. L1 sub-states are not yet implemented.
  • Added missing fields to the Precision Time Measurement extended capability.

7.66.0 (build 7128)

Device Modeling Language (DML) 1.4

  • “_” can no longer be used as the name for arbitrary declarations. Instead, it is now only permitted in particular contexts, and in these contexts, _ will affect the declaration in a way suitable for when the declaration is unused in some particular way. This feature is referred to as the discard identifier, and the contexts where it may be used are:

    • Method-local bindings (e.g. variables and input parameters.)

      When a method-local binding is given the name “_”, it will not be added to scope. This is useful for e.g. unused method parameters.

    • Index variables for object arrays

      When _ is specified as an index variable, a parameter will not be created for it, meaning it cannot conflict with any other definition, and it cannot be referenced in the code in order to get the value of the index in question. It also isn’t considered to conflict with any other definition that gives the index variable a different name. This is useful when defining an object array specification which does not depend on the index.

    • Layout member names

      When a layout member is given the name “_”, that member will not be referencable within DML code, but will still affect the memory representation of the layout. This is useful to represent e.g. reserved or padding bytes.

    Note that as a consequence of these semantics, any reference to _ in code will always resolve to the discard reference.

  • Added the discard reference “_” — a non-value expression which may be used as an assign target in order to explictly discard the result of an evaluated expression or return value of a method call (fixes SIMICS-21584.)

    Example usage:

    _ = any_expression;
_ = throwing_method();
(_, x, _) = method_with_multiple_return_values();

Python module: sloop

  • When sloop is used with Python 3.11 or newer, sloop.TaskGroup now redirects to asyncio.TaskGroup. When older Python versions are used, the class remains as a local best-effort implementation. The implementation is necessarily incomplete because of inherent limitations in the Python 3.10 API, although these limitations should rarely show up in normal usage.
  • Rewrote how sloop interacts with asyncio. This does not affect the API, but the integration with asyncio is now tighter which allows native coroutines like asyncio.delay to be used directly in sloop coroutines. The tighter integration improves asyncio ability to detect uncaught exceptions in orphaned tasks, which can uncover previously hidden errors in existing code. There is still a possibility that exceptions in orphaned tasks are delayed or even suppressed; the best is generally to rewrite them using a TaskGroup. For instance, consider the following: 
    async def reset_value_guard():
    while True:
        await wait_reset()
        assert dev.some_state == expected_reset_value
async def smoke_test()
    t = sloop.create_task(reset_value_guard())
    await sloop.wait(snoop.Seconds(cpu, 10))
sloop.run_until_complete(smoke_test())
    Before this change, an assertion failure in the reset_value_guard coroutine would remain unnoticed. After this change, the error will be detected and captured as an exception, but not until the task object is garbage collected, which will happen after the delay. The proper solution is to use a TaskGroup in the smoke_test function, which ensures all exceptions are immediately propagated: 
    async def smoke_test()
    async with TaskGroup() as tg:
        tg.create_task(reset_value_guard())
        await sloop.wait(snoop.Seconds(cpu, 10))

New Features of Intel® Simics® Simulator 7

This section highlights the main new functionality in Intel® Simics® Simulator 7 compared to the current version. Most new features in Intel® Simics® Simulator are introduced in minor versions, while major versions are used to remove deprecated functionality since breaking compatibility is not allowed in a minor version. Still, the first release of Intel® Simics® Simulator 7 has a number of new features and many more are planned to be introduced during the product’s lifetime.

In-Memory Snapshots

With this feature a user can take a snapshot of the state of the complete simulated system in run-time and revert back to this state at any point in time later in the simulation. While the mechanism for taking snapshots already exists in Intel® Simics® Simulator as part of the reverse execution feature, it has never been an accessible feature by itself. In Intel® Simics® Simulator 7, in-memory snapshots will replace the reverse execution functionality.

Use Any Python

Intel® Simics® Simulator 7 can be run with any modern Python that the user has installed. Currently Python 3.10, 3.11, 3.12 and 3.13 are supported by Intel® Simics® Simulator 7, but the list of Python versions supported may change by the time of release. Python is still bundled with the product by default in the initial release of Intel® Simics® Simulator 7, but this is planned to change (see below). With this change, users have more control over when they change the major version of Python used in the simulator.

Intel® Simics® Simulator as a Python Module

Intel® Simics® Simulator will include a “simics” Python module that users can add to their existing Python installations using the standard pip tool. Using the simulator as a Python module greatly simplifies integrating Intel® Simics® Simulator in existing test environments for example.

CMake as Default

In Intel® Simics® Simulator it has been possible to build modules using CMake as the build tool for some time. Starting with version 7, CMake will become the default build tool. GNU Make will remain supported as a legacy feature.

Semantic Versioning of Simics-Base

The Intel® Simics® Simulator package versioning has been updated to comply with the industry standard semantic versioning scheme. The previous versioning scheme used by Intel® Simics® Simulator was very similar to semantic versioning, so it is initially a small change. The biggest difference is that the minor version is now represented by the second digit group in the version number. I.e., the minor releases after Intel® Simics® Simulator 7.0.0 will be 7.1.0, 7.2.0, etc. The patch version will not be used initially.

Updated Host Requirements

The Windows version of Intel® Simics® Simulator now requires Windows 10.

Deprecations and End-of-life

API and script compatibility with Intel® Simics® Simulator 4.8 and older has been dropped. Refer to the Simics 7 Migration Guide for a complete list.

Detailed List of Changes Since 6

This section provides a list of minor changes since the Intel® Simics® Simulator 6 version that was current at the time of the initial Intel® Simics® Simulator 7 release.

Breakpoint Manager

  • Removed -reverse and -always flags for wait-for commands.

Ethernet Networking Technology Guide

  • Removed nfs-server from the guide and corresponding examples

Intel® Simics® Simulator Migration Guide

  • Updated deprecation table for command line options that are deprecated in Simics 7.

PCIe DML library

  • Added documentation of message segment routing
  • In the config_bank template: added function message.send_custom in order for devices to append custom atoms to the PCIe messages sent upstream.
