2 Language

This document does not cover C++; there is a separate style guide for that language. Older C++ code may be written in a style largely following the C rules, but new code should follow the language-specific style.

The allowed language is ISO C99. Note that some files may have stricter requirements. For instance, many public header files need to work with Microsoft Visual C, which is approximately C89 but allowing //-style comments.

Language extensions should only be used if there is a true benefit from doing so that outweighs the mess caused by conditional compilation to allow the code to build on platforms that do not support the extensions.

String literals should always be considered to have the type const char *, not char *.

Note that on Windows, interface is a reserved word or a preprocessor macro, so it cannot be used as an identifier.

All source code is written in UTF-8 without BOM. Non-ASCII characters may be used in comments and string literals where appropriate.
